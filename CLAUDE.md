# Project: "Tools By Sanat" Excel add-in

Turn the macros in Sanat's `PERSONAL.XLSB` into a single installable Excel add-in (`.xlam`) with a custom ribbon tab, custom icons, an easy installer, and online updates from GitHub.

> This is NOT a Laravel project. Ignore any Laravel/Sail notes from a parent-folder CLAUDE.md (e.g. `Downloads\CLAUDE.md`).

SECURITY MODEL (hardening round after the security review): (1) Updates are SIGNED. `version.json` carries an RSA-3072/SHA-256 signature over `ToolsBySanat|<version>|<sha256>|<url>`; the loader has the PUBLIC key built in (`keys/update-public.xml`, injected by `build-loader.ps1`) and refuses unsigned/forged updates, any url outside `https://github.com/<repo>/releases/download/`, and a staged file whose signed manifest (`pending\manifest.txt`) no longer matches (re-checked right before the swap). No public key built in = updater OFF (fails closed). The PRIVATE key is created by the owner with `new-signing-key.ps1` (encrypted with a passphrase, stored in Documents\ToolsBySanat-signing, backup on USB; never in git, never given to Claude). Per release: `release.ps1 -Version x.y.z` builds, the OWNER runs `sign-release.ps1` (asks the passphrase), `verify-manifest.ps1` checks it, then publish the release (draft, then `gh release edit --draft=false`: the repo has IMMUTABLE RELEASES on) and only then push `version.json`. (2) GitHub rulesets block deleting/force-pushing `main` and deleting/moving tags; secret scanning + push protection on; one admin, no collaborators. (3) Add-in: `modSettings.SafeText` stops text from files turning into formulas (settings values, party fields, Blinkit CSV cells); settings files are backed up (dated copies, newest 30) whenever the Settings button is used or a setting is written; `OpenTrustedWorkbook` asks before opening `JSON_preperation_FormA.xlsm` unless its SHA-256 was approved (key `trusted_sha256.<file name>` in settings.csv). Loader uses full System32 paths for cmd/certutil. Known remaining limits: unsigned Setup.exe / VBA project (SmartScreen warning), anyone with access to a user's profile can still edit settings files, Password Breaker macro is public. Loader changes need the loader file replaced (or Setup run) on every PC; VBA tip: pass typed Byte arrays (not inline Variants) to the .NET RSA call. LESSON (v0.4.1 bug, fixed in v0.4.2): the loader's first signature check used the .NET RSA COM component, which needs .NET Framework 3.5 (0x80131700 "Automation error" on PCs without it, e.g. Sanat's 2nd PC; it failed closed, update refused). The loader now verifies with the Windows CryptoAPI (advapi32: PUBLICKEYBLOB built from the XML key, CALG_SHA_256 `&H800C&` WITH the trailing & or it is negative, signature bytes reversed to little-endian) and only falls back to .NET if CryptoAPI itself is unusable. Test scenario S13/S14 in the update suite simulates a PC without .NET. v0.4.1 is immutable, so the loader fix ships as v0.4.2; PCs that ran the 0.4.1 Setup need the new loader file (or the 0.4.2 Setup) because the loader is not auto-updated.

## Decisions made
- Format: `.xlam` add-in, Windows desktop Excel only (no Mac / Excel web).
- Ribbon: `customUI14.xml` inside the `.xlam`; custom PNG icons (about 32x32, transparent) via `getImage` callback, `imageMso` as fallback for buttons without a custom icon.
- Macros are stored inside the `.xlam` (compiled `vbaProject.bin`). Keep exported source (`.bas/.cls/.frm`) in `src/` as the source of truth.
- Install on a PC: `install.ps1` (plus a double-click `Install.bat` wrapper) copies the file to `%APPDATA%\Microsoft\AddIns`, unblocks it, registers it in Excel. Manual fallback: unblock file, File > Options > Add-ins > Browse.
- Online updates via **GitHub** (user's choice), loader + main add-in design:
  - Small `ToolsBySanatLoader.xlam` is installed once and rarely changes.
  - Main `ToolsBySanat.xlam` lives next to the loader in `%APPDATA%\Microsoft\AddIns` (a folder Excel trusts by default); `ToolsBySanat_data\pending` and `\prev` hold the staged update and the rollback copy. Only the loader is registered in Excel.
  - On Excel start the loader fetches `version.json` (raw.githubusercontent.com), and if newer, downloads the `.xlam` from the GitHub Release, verifies SHA-256, swaps the file BEFORE opening it (Excel locks loaded add-ins), then loads it. On any failure keep the old version and stay silent. Keep the previous version for rollback.
  - Ribbon has a version label and a "Check for updates" button.
  - HTTPS only; hash check required.

## Known risks to check when porting macros
- References to `ThisWorkbook`, `Workbooks("PERSONAL.XLSB")`, or sheets stored in PERSONAL.XLSB break in an add-in. Scan and fix (use `ActiveWorkbook`/`ActiveSheet`, or add-in-specific storage).
- Keyboard shortcuts (`Application.OnKey`/macro options) must be reassigned.
- UserForms export as `.frm` + `.frx`; keep both.
- Macros calling `Application.Run "PERSONAL.XLSB!Name"` need updating.
- Corporate PCs may block downloads/macros; updater must fail silently and keep the old version.

## Build notes
- Building the `.xlam` (injecting VBA via COM from PowerShell) needs Excel option "Trust access to the VBA project object model" enabled on the BUILD PC only. End users do not need it.
- Excel must be closed when replacing an installed `.xlam` (file lock).
- Never run host installs/uploads silently: do not `git push`, create a GitHub repo, or publish releases without the user's explicit OK.
